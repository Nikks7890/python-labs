# Лабораторна робота №4. Рекурсія та мемоізація в Python

## Варіант 5. Merge Sort

У роботі досліджено рекурсивні алгоритми, обмеження стеку викликів у Python, відсутність оптимізації хвостових викликів (TCO) та застосування мемоізації через `functools.cache`. Для індивідуального варіанту реалізовано рекурсивне сортування злиттям (Merge Sort).

## Реалізовані алгоритми (`algorithms.py`)

- **Merge Sort** — чистий рекурсивний алгоритм, що не змінює вхідний список. База рекурсії: масив з 0 або 1 елемента.
- **Quick Sort** — реалізовано для порівняння продуктивності.
- **Обхід дерева** — рекурсивні генератори `preorder`, `inorder`, `postorder` та ітеративний пошук у ширину `bfs_level_order`.
- **Числа Фібоначчі** — рекурсивна функція `fib` з декоратором `@cache` (мемоізація) та ітеративна альтернатива `fib_iter`.

## Висновок про незмінність
Переваги: рекурсія робить код дуже коротким і зрозумілим (це чудово видно на прикладі Merge Sort та обходів дерева). Мемоізація через @cache взагалі творить магію — вона прибирає повторні обчислення, завдяки чому розрахунок чисел Фібоначчі відбувається миттєво, а не роками.

Накладні витрати: через відсутність TCO в Python стек викликів швидко переповнюється (ліміт ≈1000), тому для глибоких структур доводиться використовувати ітеративні цикли. Також рекурсія створює нові списки, що вимагає додаткової пам'яті. У мікробенчмарку tests/test_performance.py (100 ітерацій сортування масиву з 500 елементів) рекурсивний Merge Sort виконався за ≈ 0.0012 с на один запуск. Це, звісно, повільніше за вбудовану функцію sorted() (написану на C), але для чистої реалізації на Python це цілком гідний результат.
